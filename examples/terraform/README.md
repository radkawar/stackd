# Terraform: object bytes and queue messages

Complete [shared preparation](../README.md) first. No Docker runtime is needed.
The AWS provider is pinned to `hashicorp/aws` **5.100.0**; Terraform CLI accepts
>= 1.5 and < 2. The checked-in `.terraform.lock.hcl` was generated by
`terraform providers lock` for Linux/macOS amd64/arm64 using HashiCorp-signed
[release checksums](https://releases.hashicorp.com/terraform-provider-aws/5.100.0/terraform-provider-aws_5.100.0_SHA256SUMS).
It retains both archive (`zh`) and package-content (`h1`) hashes. No provider
executable is vendored. The executable workflow was exercised with Terraform
1.15.9 and provider 5.100.0 on Linux amd64; other host execution is not implied.

```sh
"$EXAMPLE_PYTHON" examples/terraform/run.py --port 14661
```

The runner copies configuration and lock into a new owned working directory,
starts its own controller, then runs these **real Terraform commands** there:

```text
terraform init -input=false -lockfile=readonly
terraform apply -input=false -auto-approve
terraform output -json application
# Signed SDK verification consumes these outputs.
terraform plan -input=false -detailed-exitcode -out=noop.tfplan
# Must exit 0; exit 1 (failure) and 2 (drift) both fail the example.
terraform apply -input=false -auto-approve noop.tfplan
# Signed SDK verification repeats with new unique object/message bytes.
terraform destroy -input=false -auto-approve
terraform show -json
```

`local.auto.tfvars.json` supplies only the owned loopback endpoint and a unique
name. `outputs.json` retains bucket, queue URL and SSM parameter name. The
producer puts non-text bytes in S3 and sends a JSON manifest with their SHA-256
through SQS. The consumer verifies message identity/body, downloads and compares
the exact object bytes, deletes the message, and asserts it is not delivered
again. It also reads the provisioned SSM value. Objects are removed before
Terraform destroys the bucket; `force_destroy` is deliberately not used.
Finally signed API calls must report all three resources absent, and Terraform
state must contain no resources.

Every provider service used by this configuration has an explicit local
endpoint, including IAM and STS metadata paths. `s3_use_path_style` avoids DNS
bucket-name routing. Only fixture credentials are used. Keep additions to this
configuration subject to the same rule: add an endpoint for any new service
before adding a resource/data source. This is a local application workflow,
not evidence of complete Terraform provider coverage or of scoped IAM access
(the application assertions deliberately use the local bootstrap identity).

## Lock updates and offline preparation

A maintainer changing the provider version should use Terraform's native lock
workflow in an owned scratch directory, review the publisher-signed checksum
result, and commit only the reviewed source lock/configuration change:

```sh
TF_PREP="$(mktemp -d /tmp/stackd-tf-prep.XXXXXX)"
cp examples/terraform/main.tf examples/terraform/.terraform.lock.hcl "$TF_PREP/"
terraform -chdir="$TF_PREP" providers lock \
  -platform=linux_amd64 -platform=linux_arm64 \
  -platform=darwin_amd64 -platform=darwin_arm64
```

For an offline execution host, prepare an archive-layout filesystem mirror
while connected. No AWS provisioning occurs during `providers mirror`:

```sh
TF_MIRROR="$(mktemp -d /tmp/stackd-tf-mirror.XXXXXX)"
terraform -chdir="$TF_PREP" providers mirror \
  -platform=linux_amd64 -platform=linux_arm64 \
  -platform=darwin_amd64 -platform=darwin_arm64 "$TF_MIRROR"
"$EXAMPLE_PYTHON" examples/terraform/run.py --port 14661 \
  --provider-mirror "$TF_MIRROR"
```

Transfer that mirror to the offline host and use its absolute path. This flag
writes a private `filesystem_mirror` configuration with **no direct fallback**;
a missing archive fails instead of downloading. The runner intentionally ignores
ambient `TF_CLI_CONFIG_FILE` and provider development overrides. Its readonly
lockfile mode verifies the selected archive without modifying the source lock.
See [shared cleanup](../README.md#cleanup-and-evidence) for retained run files.
Remove only your printed/created scratch directories when finished; never
commit `.terraform/`, provider mirrors, plans, state, or generated outputs.
